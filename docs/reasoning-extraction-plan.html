Plan: Zero-Latency LLM Reasoning Extraction

Glass-Box Tracer enhancement — scl-core-v2 → chat-wonder-v2-api
Created: 2026-05-25  |  Status: Pending implementation

Problem

The glass-box tracer currently shows the what of each R-CCAM stage — which tool was chosen, what arguments were passed, what it returned. When a tool is selected, the tracer displays the tool's declared description as a proxy for "why," but this is generic. It does not explain the LLM's actual decision: what in the user's message or prior context led it to choose that specific tool at that moment.

Solution

After the LLM selects a tool, spin up a daemon background thread that makes a small secondary LLM call (gpt-4o-mini, max 80 tokens) asking "why this tool, given what the user said?" and broadcasts the answer as a ◈ COGNITION event.

Zero latency impact: The main function chain does not wait for the background thread. It proceeds immediately to HITL check, duplicate check, and tool execution. The reasoning explanation arrives in the tracer ~0.5–2 seconds later — concurrent with or just before the ACTION result.

Step 1 — Add Helper Function (~line 165, near broadcast_trace)

def _async_explain_tool_choice(tool_name, tool_desc, args, last_user_msg,
                                 prior_outputs, openai_client, model, session_id):
    """Daemon thread — explains why the LLM chose this tool. Never blocks the main loop."""
    try:
        facts_ctx = ""
        if prior_outputs:
            facts_ctx = "\n\nPrior tool results already in context:\n" + "\n".join(
                f"  - {n}: {str(v)[:100]}" for n, v in prior_outputs[-3:]
            )
        prompt = (
            f"An AI assistant just decided to call `{tool_name}` "
            f"with arguments: {json.dumps(args, ensure_ascii=False) if isinstance(args, dict) else str(args)}\n\n"
            f"Tool purpose: {tool_desc}\n\n"
            f"The user said: \"{last_user_msg[:300]}\""
            f"{facts_ctx}\n\n"
            "In exactly ONE sentence, explain why this tool call is the right next step. "
            "Be specific about what in the user's request or prior context triggered this choice."
        )
        resp = openai_client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": prompt}],
            max_tokens=80,
            temperature=0.0,
            stream=False,
        )
        explanation = resp.choices[0].message.content.strip()
        broadcast_trace("cognition", f"Reasoning: {explanation}", session_id)
    except Exception:
        pass  # best-effort — never interrupt the main loop

Trade-offs

This approach (background thread) Prompt chain-of-thought (alternative)
Main loop latency Zero +0.5–2s per tool call
Explanation quality Good — uses actual user message + prior results Better — LLM explains before it acts
Cost 1 extra gpt-4o-mini call per tool (~80 tokens) Longer primary call, same model
Streaming client sees Unchanged Reasoning text in the chat stream
